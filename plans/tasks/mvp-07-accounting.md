# MVP-07: Учёт трафика, квоты, финализация

**Веха:** M6 · **FR:** FR-3.5.1–3.5.5, FR-3.11.4, NFR-3 · **Статус:** ⬜ не начато

## Цель
Fail-closed учёт трафика WG/AWG: опрос transfer, эпохи, базлайны, квоты с UTC-сбросом,
автоотключение при исчерпании, финализация linked-peer'ов.

## Что сделать
1. `app/accounting/collector.py` — фоновая задача (интервал 60 с, настройка 30–300):
   - `wg/awg show <iface> transfer` по всем инстансам; алиасы одного контейнера — один
     опрос; семплы: connection ID, полный ключ протокола, client ID, server ID;
   - дубликаты владельцев одного физического peer'а — логируются и пропускаются.
2. `app/accounting/epochs.py` — хэш эпохи: container ID + start time + PID, host boot ID,
   ifindex, inode/ctime UAPI-сокета; метаданные до и после чтения счётчиков; смена
   эпохи/сброс ⇒ `traffic_accounting_gap`, `counters_verified_final=false`, итоги
   пользователя не трогаются.
3. `app/accounting/service.py`:
   - базлайны и lifetime-итоги переживают перезапуск;
   - календарный сброс квот — UTC (сохранение сырых базлайнов);
   - недоступность SSH в неизменной эпохе — догон при следующем успешном чтении;
   - квоты: `traffic_used/total/limit`; исчерпание ⇒ автоотключение (`disable_reasons`:
     `quota`), применение ≤ 2 интервалов опроса; expiration (UTC); ручные причины;
     access reconciliation при смене статусов.
4. `app/accounting/finalization.py` — финализация linked-peer'а (FR-3.11.4): чтение
   финального счётчика, коммит дельты, tombstone в `accounting_recoveries`; нечитаемый
   счётчик ⇒ fail-closed 409 с `can_force` и ретраем `allow_unverified`.
5. Перенос `user_connections` учётных полей в нормальную структуру (миграция 0002 при
   необходимости).

## Тесты
- unit: парсер transfer; хэш эпохи (детерминизм/смена); расчёт дельт и календарного
  сброса (UTC, freeze time).
- integration: цикл опроса на mock-SSH; смена эпохи → gap, без обнуления; квота
  исчерпана → peer отключён ≤ 2 циклов; финализация happy-path и 409; перезапуск
  панели — базлайны целы.

## Вне скоупа шага
Shared-учёт share-страниц (этап 2), UI-графики (MVP-08 только числа).

## Критерий приёмки
Счётчики растут между опросами; сброс счётчика фиксируется диагностикой, а не обнулением;
квота отключает peer вовремя; `pytest -q` зелёный.
