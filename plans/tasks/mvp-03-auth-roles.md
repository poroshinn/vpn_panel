# MVP-03: Аутентификация, сессии, роли, audit-каркас

**Веха:** M2 · **FR:** ТЗ §2.2–2.3, FR-3.16.2, FR-3.10.3 · **Статус:** ✅ выполнено (2026-11-10)

## Цель
Полный вход в панель: argon2id, подписанные cookie-сессии, матрица ролей, brute-force
защита, CAPTCHA, каркас audit trail.

## Что сделать
1. `app/core/security.py` — argon2id-хэширование; AES-256-GCM шифрование/расшифрование
   (сразу, нужно для следующего шага); `PANEL_MASTER_KEY` становится **обязательным**
   (генерация и сохранение в volume при первом старте, если не задан).
2. `app/auth/sessions.py` — подписанные cookie-сессии (`SECRET_KEY`): absolute 7 дней,
   idle 24 ч (настраивается в `settings`); инвалидация при `enabled=false`, понижении
   роли, `role=none`.
3. `app/auth/service.py` — вход; первый `admin/admin` с обязательной сменой пароля;
   brute-force: прогрессивная задержка на пару логин+IP (5 неудач → 30 с, экспонента),
   блокировка IP по лимиту.
4. `app/auth/captcha.py` — процессно-локальное хранилище challenge, атомарное
   «потребление» ответа; включается настройкой.
5. `app/auth/dependencies.py` — `require_role(...)`, единая точка авторизации по
   матрице ТЗ §2.2; 403 на `/api/*` без валидной сессии (кроме `/api/auth/*`).
6. `app/audit.py` (или `app/core/audit.py`) — запись событий в `audit_log` (UTC, actor,
   действие, объект, IP, результат) + зеркало в `logs/audit-YYYY-MM-DD.log`.
7. Страница логина (Jinja2) + `POST /api/auth/login`, `POST /api/auth/logout`.

## Тесты
- unit: хэши/верификация argon2id; AES-GCM roundtrip; CAPTCHA-потребление атомарно.
- integration: логин/логаут; brute-force задержки; сессия мертва после disable/role-none;
  матрица ролей (support не может создать сервер и т.д. — параметризованный тест);
  audit-события фиксируются (БД + файл); секреты не попадают в логи.

## Вне скоупа шага
Bearer-токены (MVP-11), TOTP (этап 2+), Telegram, страницы кроме логина.

## Критерий приёмки
Вход `admin/admin` → обязательная смена пароля; роли разграничены по матрице;
неудачные входы логируются; `pytest -q` зелёный.
