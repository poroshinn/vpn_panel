# MVP-08: Пользователи панели

**Веха:** M7 · **FR:** FR-3.6.1–3.6.5 · **Статус:** ⬜ не начато

## Цель
CRUD пользователей, роли, привязка подключений, автоматическая инвалидация, экспорт.

## Что сделать
1. `app/users/service.py`:
   - CRUD: имя, роль (`admin/support/user/none`), пароль (обязателен кроме `none`),
     Telegram ID, enable/disable одной кнопкой;
   - управление подключениями пользователя: привязка/отвязка (FR-3.6.2);
   - отвязка владельца (FR-3.6.3): отключённые/отсутствующие peer'ы — напрямую;
     активные — `stop: true` (остановка на ноде перед отвязкой); нечитаемый финальный
     счётчик — `allow_unverified: true`; lifecycle-lock на время операции;
   - автоматическая инвалидация (FR-3.6.4): disable ⇒ сессии и Bearer-токены (когда
     появятся) мгновенно недействительны; понижение до `none` — отзыв прав токенов;
   - экспорт списка подключений пользователя и конфигов — admin/support (FR-3.6.5).
2. API `/api/v1/users/...`; страницы «Пользователи» (карточки, роли, квоты, статусы).

## Тесты
- integration: CRUD; смена роли мгновенно режет доступ (сессия); отвязка активного
  peer'а идёт через stop; экспорт доступен admin/support, но не user; audit-события.

## Вне скоупа шага
Группы (этап 2), self-service (этап 2), share-setup endpoint (MVP-09), Bearer-токены
(MVP-11 — но hook для инвалидации заложить).

## Критерий приёмки
Пользователи создаются/отключаются; доступ исчезает мгновенно; отвязка с финализацией
работает по правилам FR-3.6.3; `pytest -q` зелёный.
