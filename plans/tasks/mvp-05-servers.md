# MVP-05: Серверы — CRUD, онбординг, дашборд-данные

**Веха:** M4 · **FR:** FR-3.1.1–3.1.6, FR-3.1.8, FR-3.1.9, FR-3.1.10*, FR-3.13.1–3.13.3 · **Статус:** ✅ выполнено (2026-11-10)
\* FR-3.1.10 (публичный адрес инстанса) — таблица в БД сейчас, UI — в MVP-08.

## Цель
Полный цикл управления серверами: мастер добавления с верификацией, CRUD, сортировка,
перезагрузка, данные для дашборда.

## Что сделать
1. `app/servers/service.py`:
   - добавление сервера (адрес, SSH-порт, логин, пароль/ключ) — admin-only; секреты
     шифруются at rest (FR-3.1.13);
   - автоматическая верификация после добавления (FR-3.1.2): обнаружение установленных
     протоколов/контейнеров, существующих пользователей — через SSH-пробы MVP-04;
   - `uid` — стабильный идентификатор (генерация при добавлении);
   - редактирование, удаление (с guard'ами: что делать с подключениями — см. ТЗ),
     drag-and-drop сортировка (порядок в `sort_order`);
   - перезагрузка сервера (SSH reboot) — admin-only.
2. `app/api/servers.py` — REST `/api/v1/servers` (+ping-проба, статистика хоста);
   ошибки — единый JSON.
3. Jinja2-страницы: дашборд (карточки, ping-индикаторы, статусы), страница сервера,
   мастер `/servers/new`. Данные живые — пока polling, SSE — в MVP-08.

## Тесты
- integration: CRUD + сортировка переживает перечитывание; uid стабилен;
  онбординг-детекция на mock-SSH-ноде; 403 для support/user на мутирующие операции;
  audit-события создания/удаления.

## Вне скоупа шага
Установка протоколов (MVP-06), wipe (этап 2), публичный адрес UI (этап 2 UI).

## Критерий приёмки
Сервер добавляется на mock-ноде, протоколы обнаруживаются; дашборд рендерится;
сортировка и перезагрузка работают; `pytest -q` зелёный.
