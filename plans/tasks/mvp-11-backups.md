# MVP-11: Бэкапы и восстановление

**Веха:** M10 · **FR:** FR-3.10.10, FR-3.11.1, FR-3.11.3, FR-3.11.4(связка), FR-3.11.7 · **Статус:** ⬜ не начато

## Цель
Снапшоты SQLite, ежедневный автобэкап в Telegram, in-panel restore с protected-профилем,
восстановление из Telegram-бэкапа.

## Что сделать
1. `app/backups/snapshot.py` — безопасный SQLite-снапшот (в безопасный момент записи,
   WAL-checkpoint), gzip; локальная ротация `backups/` (7 файлов).
2. `app/backups/telegram.py` — ежедневная отправка ботом админу (время UTC из настроек);
   лимит файла Telegram учитывается (превышение — отправка без вложения с инструкцией);
   бот не настроен ⇒ деградация в локальную ротацию + алерт (FR-3.10.13).
3. `app/backups/restore.py` — in-panel restore (FR-3.11.1):
   - валидация файла (`.db`/`.db.gz`, SQLite integrity check, версия схемы);
   - превью (версия, число записей, предупреждения);
   - обязательный пред-restore снапшот текущей БД (скачиваемый);
   - атомарная замена + перезапуск внутренних кэшей/соединений без остановки процесса;
   - **protected-профиль** (FR-3.11.3): по умолчанию сохраняются текущие счётчики/
     базлайны/ownership; «полное восстановление» — только подтверждение текстом;
     попытка отмотать защищённые записи без подтверждения ⇒ 409;
   - ошибка restore ⇒ автооткат к пред-restore снапшоту + понятная ошибка.
4. Формат Telegram-бэкапа идентичен скачиваемому снимку — один валидатор (FR-3.11.7).
5. UI: вкладка «Бэкапы» в настройках (скачать / загрузить / восстановить).
6. Примечание: на этом шаге Telegram-интеграция — общий клиент отправки файлов; полный
   бот (команды, роли) — Этап 2; алерты-тумблеры — MVP-12.

## Тесты
- integration: снапшот/ротация; restore happy-path; 409 без текст-подтверждения;
  автооткат при сбое; protected-записи не затёрты в merge-профиле; файл из «Telegram»
  (тот же формат) восстанавливается; версия схемы новее текущей ⇒ отказ.
- unit: gzip-валидатор; проверка integrity.

## Вне скоупа шага
ZIP-архив состояния (этап 2/3), офлайн-восстановление (этап 3).

## Критерий приёмки
Сценарий ТЗ §5.5–5.6 выполняется end-to-end на тестовой БД; `pytest -q` зелёный.
