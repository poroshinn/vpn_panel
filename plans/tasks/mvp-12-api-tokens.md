# MVP-12: API v1, Bearer-токены

**Веха:** M11 · **FR:** FR-3.12.1–3.12.5, §2.3 (токены) · **Статус:** ⬜ не начато

## Цель
Версионированный API, Bearer-токены с TTL/ротацией, Swagger/ReDoc, единые ошибки.

## Что сделать
1. `app/api/v1/` — группировка маршрутов (FR-3.12.3): Authentication, Servers,
   Protocols, Connections, Users, Self-service (заглушка), Sharing, Settings,
   API Tokens, System Templates (HTML). `/api` — алиас на v1.
2. `app/auth/tokens.py`:
   - токены `awp_...`; в БД только SHA-256; полное значение — однократно;
   - наследует роль создателя (admin/support); TTL и дата истечения (nullable);
   - ротация (новый + отзыв старого) и отзыв в один клик;
   - автопрекращение при отключении/понижении владельца (hook из MVP-08);
   - каждый endpoint, принимающий сессию, принимает и токен.
3. Единый обработчик ошибок: `{"error_code", "message", "details"}` (FR-3.12.5);
   `app/api/errors.py` — реестр кодов.
4. Rate-limit (FR-2.3): скользящее окно на `/api/*` (настраивается), повышенные лимиты
   на auth-эндпоинты.
5. Swagger `/docs`, ReDoc `/redoc` (FR-3.12.2).

## Тесты
- integration: токен работает на всех сессионных эндпоинтах; TTL истёк ⇒ 401; отзыв
  мгновенный; support-токен не открывает admin-only операции; наследование роли;
  rate-limit срабатывает; ошибки единообразны.

## Вне скоупа шага
Invite/бот (этап 2), метрики Prometheus (этап 2).

## Критерий приёмки
Сценарий ТЗ §5.4 (внешняя интеграция) выполняется; `pytest -q` зелёный.
