# ADR-0002: SSH-библиотека — Paramiko (threading) вместо asyncssh

- **Статус:** accepted
- **Дата:** 2026-11-10
- **Связь:** FR-3.1.5, FR-3.1.8, FR-3.1.9, FR-3.1.11, FR-3.1.13 (ТЗ); NFR-2 (неблокирующий I/O)

## Контекст

SSH-слой панели (MVP-04) выполняет к нодам: команды (`docker ps`, скрипт статистики
хоста), SFTP/чтение файлов, интерактивную установку протоколов. Нужна библиотека,
совместимая с asyncio-архитектурой (правило AGENTS.md: весь I/O — неблокирующий).
Рассматривались `asyncssh` и `paramiko` (последняя уже заявлена в ТЗ §«Стек» как
«Paramiko / asyncssh»).

## Решение

Используем **Paramiko**; все блокирующие вызовы — строго через `asyncio.to_thread`
(или выделенный `ThreadPoolExecutor` в пуле соединений). Обёртки в `app/ssh/pool.py`
делают API полностью асинхронным.

Обоснование:

1. **Секретность и аудит кода.** Paramiko — чистый Python, минимум нативных
   зависимостей (cryptography уже в проекте для AES-GCM). Меньшая поверхность
   поставки, предсказуемая сборка в Docker.
2. **Стабильность API.** Paramiko годами не ломает обратную совместимость;
   asyncssh чаще меняет сигнатуры и поведение аутентификации между мажорами.
3. **Точечная параллельность.** Панель держит по одному соединению на ноду
   (десятки нод максимум), workload — короткие команды раз в N секунд. GIL-потоки
   здесь не узкое место: время уходит в сеть, а не в CPU.
4. **Пробы параллельны.** TCP-ping — чистый asyncio (`open_connection`), без
   потоков вовсе; SSH-пробы — пул из ≤ размеру пула потоков.

## Альтернативы

- **asyncssh** — нативный asyncio, отсутствие `to_thread`. Отклонено: дополнительная
  зависимость (правило 10 AGENTS.md требует ADR — настоящий документ; но выигрыш
  минимален при данном профиле нагрузки), история мажорных изменений API (2.x → 3.x),
  часть функций (расширенный SFTP-стат) платформа-зависима.
- **Поддержать обе с абстракцией транспорта** — отклонено: удвоение поверхности
  тестирования без практической выгоды; при необходимости замена инкапсулирована
  в `app/ssh/pool.py` (единственное место с `paramiko`-импортами).

## Последствия

- +0 новых зависимостей: `paramiko>=3.4` уже в `pyproject.toml`.
- Запрещено вызывать `paramiko.*` напрямую вне `app/ssh/` (кроме тестов).
- Каждый SSH-вызов имеет таймаут: `asyncio.wait_for` вокруг `to_thread`
  (сетевой `timeout` в `SSHClient.connect`, `channel.settimeout` для exec).
- Пул ограничен по числу соединений; неиспользуемые соединения закрываются по TTL.
- Потоки не должны жить дольше вызова: `asyncio.to_thread` возвращается после
  завершения команды — утечек потоков нет.
