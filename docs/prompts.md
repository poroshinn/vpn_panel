# Промты для работы с ИИ-агентом

> Сопровождает процесс из [`AGENTS.md`](../AGENTS.md) §5. Общий принцип каждого промта:
> сначала агент читает `AGENTS.md` + `plans/progress.md`, затем действует строго в рамках
> задачи. Коммит после каждого шага — обязателен (см. раздел «Процесс» ниже).

## Универсальная шапка (вставляйте в начало любого промта)

```text
Прочитай AGENTS.md, docs/conventions.md и plans/progress.md.
Работай по правилам проекта: UTC, no-echo секретов, forward-only миграции,
идемпотентные мутации, единые JSON-ошибки, тесты обязательны.
Не выходи за рамки задачи. По завершении обнови plans/progress.md и сделай коммит.
```

---

## 1. Шаг разработки (основной цикл)

```text
{шапка}

Выполни задачу {mvp-XX} из plans/tasks/{mvp-XX}.md целиком:
- реализуй код по разделу «Что сделать»;
- напиши тесты из раздела «Тесты»;
- проверь: pytest -q — зелёный;
- не делай ничего из раздела «Вне скоупа шага»;
- проверь критерий приёмки и перечисли его выполнение.
Заверши: обнови plans/progress.md (статус, дата, заметки) и закоммить
сообщением вида "feat(mvp-XX): <суть>".
```

**Коммит-процесс (каждый шаг):**

```text
git add -A
git commit -m "feat(mvp-XX): <что сделано>"   # или fix/docs/refactor
# push выполняет пользователь
```

## 2. Устранение ошибок и неполадок (Debug)

### 2.1. Общий отладочный промт

```text
{шапка}

Режим отладки. Симптом: <опиши ошибку / вставь traceback / текст из лога>.
Действуй системно:
1) воспроизведи (команда/тест), 2) локализуй корневую причину — гипотезы
подтверждай фактами из кода, не правь «наугад», 3) предложи минимальный фикс.
Секреты из логов не цитируй. После фикса — регрессионный тест, покрывающий
причину, и коммит "fix: <корневая причина>".
```

### 2.2. Тест падает

```text
{шапка}

Тест <имя теста> падает: <вывод pytest>. Определи: баг в коде, во флаке/фикстуре
или изменилось требование. Ничего не «чинь» подгонкой теста под код без
подтверждения причины. Если это регресс — добавь в тест комментарий со ссылкой
на причину и коммит "fix: ..." либо "test: ..." в зависимости от вывода.
```

### 2.3. Панель не стартует / миграция упала

```text
{шапка}

Панель не стартует: <вывод uvicorn / pytest>. Проверь порядок старта
(app/main.py lifespan): логгер → БД → миграции (app/db/migrator.py).
Внимание: правила проекта — миграции только forward, при сбое панель не
стартует с диагностикой. Найди корневую причину, предложи фикс и,
если миграция уже частично применилась на испорченной dev-БД, предложи
безопасный путь восстановления (снапшот из backups/pre-migrate/).
```

### 2.4. Подозрение на утечку секрета

```text
{шапка}

Проверь утечку: <что и где увидел>. Действия: grep по логам и API-ответам,
проверь санитайзер (app/core/logging.py), no-echo в сериализаторах, шифрование
at rest (app/core/security.py). Найденное в открытом виде — устрани немедленно,
добавь тест no-echo, коммит "fix(security): ..." — внеочередной, без ожидания шага.
```

## 3. Доработки и фичи (вне текущих задач)

### 3.1. Новая фича по ТЗ

```text
{шапка}

Требование: <FR-3.X.Y из ТЗ>. Сначала — план в режиме architect: какие модули
затрагиваем (docs/architecture.md), какие таблицы/миграции нужны, веха в
plans/roadmap.md. Утверди план, затем создай файл plans/tasks/feat-<slug>.md
по образцу задач mvp-* и выполни его как обычный шаг (раздел 1 этого файла).
```

### 3.2. Рефакторинг

```text
{шапка}

Рефакторинг: <что и почему>. Ограничения: поведение не меняется (тесты —
зелёные до и после), публичное API не ломается, миграции схемы не трогаем.
Малые атомарные коммиты "refactor: ...".
```

### 3.3. Изменение требования / уточнение ТЗ

```text
{шапка}

Уточнение требования: <что меняется>. Проверь: не противоречит ли матрице
ролей (ТЗ §2.2) и железным правилам (AGENTS.md §3). Если меняет архитектуру —
сначала новый ADR в docs/decisions/, затем код. Обнови релевантные FR-ссылки
в задачах и docs/.
```

### 3.4. Новая зависимость

```text
{шапка}

Предлагается зависимость: <имя, зачем>. По правилу 10 AGENTS.md: внеси в
pyproject.toml и requirements.txt, создай краткий ADR (docs/decisions/) с
обоснованием и альтернативами, затем используй.
```

| Обновить прогресс вручную | «Обнови plans/progress.md: задача {XX} — статус, дата UTC, заметки: <…>.» |
