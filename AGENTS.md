# AGENTS.md — контекст проекта для ИИ-агентов

> Прочитай этот файл перед любыми изменениями кода. Он — краткая «паспорт» проекта;
> полный источник истины — «Техническое задание — Amnezia Web Panel.md» (версия 1.2).

## 1. Что это за проект

Веб-панель управления VPN-инфраструктурой (аналог Amnezia Web Panel): управление
удалёнными серверами Ubuntu по SSH (Docker-контейнеры протоколов), учёт трафика и квот,
роли, self-service, шеринг конфигураций, бэкапы.

## 2. Технологический стек (фиксирован)

- **Python 3.11–3.13**, FastAPI, asyncio (весь I/O — неблокирующий)
- **Paramiko / asyncssh** — SSH к нодам (см. ADR-0002 при появлении)
- **Jinja2** — HTML-шаблоны; **Vanilla JS** (без фронтенд-фреймворков)
- **SQLite** (`panel.db`, WAL, асинхронные блокировки записи `asyncio.Lock`), миграции —
  встроенный мигратор (`schema_version`, только forward)
- **Docker / docker-compose**, volume `amnezia_data`
- Пароли — argon2id; секреты серверов — AES-256-GCM под `PANEL_MASTER_KEY`
- Тесты — pytest (+ Playwright для E2E на поздних этапах)

## 3. Железные правила (нарушать нельзя)

1. **Один процесс панели.** In-process блокировки; SQLite — один writer.
2. **UTC везде.** Все метки времени в БД, логах, API и календарных сбросах квот — UTC.
   Таймзона применяется только при отображении.
3. **Секреты никогда не покидают процесс в открытом виде**: no-echo в API-ответах,
   статусах, логах, ошибках. SSH-пароли/ключи — только шифрованными at rest.
   Bearer-токены и share-пароли хранятся только как SHA-256/argon2-хэши.
4. **Логи — текстовые файлы** `logs/panel-YYYY-MM-DD.log`, ретеншн 7 дней, обязательный
   санитайзер на уровне логгера.
5. **Fail-closed учёт трафика**: недоказанные счётчики помечаются
   `counters_verified_final=false`; никаких обнулений «для успеха».
6. **Идемпотентность мутаций**: операции создания peer'ов / восстановления — с
   `operation_id`, ретрай безопасен.
7. **Миграции схемы — только forward.** Перед применением — pre-migrate снапшот БД.
8. **Матрица ролей (раздел 2.2 ТЗ) — источник истины** по разграничению доступа.
   Не расширять полномочия формулировками FR.
9. **API**: машинные эндпоинты под `/api/v1/`; ошибки — единый JSON
   `{"error_code": "...", "message": "...", "details": {...}}`.
10. **Не расширять зависимости** без внесения их в `pyproject.toml` и краткого
    обоснования в ADR (`docs/decisions/`).

## 4. Структура репозитория

```
app/
  main.py            # точка входа FastAPI
  core/              # config, security (хэши, шифрование), logging, rate-limit
  db/                # database.py (aio-доступ), migrations/ (упорядоченные)
  auth/              # сессии, роли, brute-force, CAPTCHA, Bearer-токены
  ssh/               # пул соединений, known-hosts, circuit breaker, пробы
  servers/           # CRUD серверов, онбординг, статусы, статистика хоста
  protocols/         # установка/удаление протоколов, peers, конфиги
  accounting/        # счётчики, эпохи, базлайны, квоты, финализация
  users/             # пользователи, группы (этап 2), ownership
  sharing/           # share-токены, публичная страница /share/{token}
  backups/           # снапшоты, restore, автобэкап в Telegram
  api/               # /api/v1 роутеры
  web/               # Jinja2-шаблоны, статика, SSE
  i18n/              # en/ru локализация
docs/
plans/
  roadmap.md         # вехи
  tasks/             # атомарные задачи (одна задача = один шаг ИИ)
  progress.md        # журнал прогресса — обновлять после каждого шага!
tests/
```

## 5. Как вести пошаговую разработку

1. Открой `plans/progress.md` → возьми первую незакрытую задачу → открой её файл в
   `plans/tasks/`.
2. Задача выполняется **целиком**: код + тесты + запись в `plans/progress.md`.
3. Не выходи за рамки задачи (раздел «Вне скоупа шага»).
4. Каждая задача ссылается на FR из ТЗ — сверяйся с формулировкой.
5. Завершил задачу → пометь в `plans/progress.md` (статус, дата, заметки) →
   следующий шаг только после подтверждения пользователем.

## 6. Терминология

См. `docs/glossary.md`. Ключевое: **инстанс протокола** = контейнер на ноде
(ключ вида `awg2`, `awg2__2`); **peer/подключение/клиент** — синонимы;
**эпоха** — идентичность физического peer'а для детекции сброса счётчиков.
